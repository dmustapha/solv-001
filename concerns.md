# Concerns Snapshot — Warroom V3
**Hackathon:** Agora Agents Hackathon (Canteen × Circle × Arc)
**Date:** 2026-05-19

---

## CRITICAL CONCERNS [C] — Idea eliminated if violated

**C1. Time is not a constraint** — scope must be achievable in 7-10 build days by a solo developer. No moonshots.

**C2. arc-canteen CLI mandatory** — ALL Arc testnet interactions MUST use arc-canteen CLI per hackathon brief (§0, §17). Any idea that cannot integrate with arc-canteen is ineligible.

**C3. Uniqueness is non-negotiable** — zero verified competitors in this exact niche. "Space is crowded but niche is empty" is acceptable — be specific. Any idea with confirmed competitors is eliminated.

**C4. Circle tools must be architecturally motivated** — every Circle tool used must pass the substitution test: "If I removed this tool, does the core value proposition collapse?" Decorative integration = eliminated.

**C5. Real humans test** — name specific humans with a specific problem. "DeFi users" is not specific. Eliminated if only hypothetical future users.

**C6. Traction must be self-evidencing** — traction evidence must be on-chain by design, not manufactured or staged. Human-controlled pipelines where the builder controls both sides = ineligible.

**C7. Demo must show real Arc transactions** — Arc blockchain explorer segment showing real testnet transactions is mandatory. No mock data, no simulated confirmations.

**C8. Cumulative corrections carried forward** — all V1 and V2 corrections apply cumulatively. Nothing dropped.

**C9. Significant problem + builder conviction** — problem large enough to matter AND builder would build this without a prize. "This could win" is not sufficient.

**C13. Day-1 users exist TODAY** — identifiable, reachable people who have this problem now. Not "once the ecosystem matures."

---

## IMPORTANT CONCERNS [I] — Score penalty if violated

**I1. Innovation ≥7/10** — V2 mandate. Execution-only plays disqualified. Ideas that any team can clone in 14 days score lower on Innovation regardless of execution quality.

**I2. Everything on devnet/testnet** — mainnet deployments not appropriate for hackathon. Testnet only.

**I3. Agentic sophistication is real** — AI must genuinely decide, not just automate. Mechanical wrappers that call APIs in sequence without reasoning loops score low on Agentic Sophistication (30% weight criterion).

**I4. Demo feels like a real product** — terminal-only demos are acceptable but a UI dashboard is strongly preferred. Demo should feel polished, not like a prototype.

---

## ADVISORY CONCERNS [A]

**A1. Multi-track eligibility** — qualifying for Circle Tool Integration + Canteen Social increases prize ceiling. Preferred if achievable without scope creep.

**A2. Post-hackathon path is visible** — judges favor ideas that could become real products, not just hackathon demos.

---

## PER-HACKATHON CONCERNS (Agora-specific)

**P1. V3-MANDATE** — Fix ReasonTrace Traction weakness (6/10 on a 30%-weighted criterion) OR find a new category with stronger self-evidencing traction. This is the V3 primary mandate. Any winner that also scores ≤6/10 on Traction fails this mandate.

**P2. No Section 10 mirrors** — ideas that mirror the brief's own RFB examples (perp trading agents, market makers) are obvious to judges who wrote the brief. These score low on Innovation.

**P3. Nanopayments substitution test** — if Nanopayments are used, they must be architecturally necessary. Using them as a payment rail where any transfer would do = fails substitution test.

**P4. arc-canteen Day 0 validation** — any winning idea must be validated with arc-canteen CLI on Day 0 before architecture decisions. This is explicitly required by the hackathon brief.
